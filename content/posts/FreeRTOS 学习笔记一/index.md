## ARM Cortex-M 内核基础

### 1. HardFault（硬故障）

HardFault 是处理器检测到严重执行异常后产生的系统异常，表示程序执行过程中出现了无法由普通异常机制处理的故障。

Cortex-M 处理器将异常分为中断和系统异常两大类。系统异常包括 Reset、NMI、HardFault 等。其中，HardFault 属于内核级系统异常，优先级高于所有可配置优先级的异常，但低于 NMI。

HardFault 并不对应某一种具体错误，表示处理器进入需要特殊处理的故障状态。

#### 1.1 典型触发原因

- 非法内存访问。
    
- 总线访问异常。
    
- 指令使用错误。
    
- 栈和上下文破坏。
    
- 与中断、DMA 及并发访问相关的隐蔽问题。
    

#### 1.2 异常进入时处理器保存的内容

当 HardFault 发生时，处理器会自动执行异常入栈。

标准情况下，内核会将以下寄存器压入当前使用的栈中，形成基本栈帧：

|寄存器|作用|
|---|---|
|R0～R3|通用寄存器|
|R12|通用寄存器|
|LR|链接寄存器|
|PC|程序计数器|
|xPSR|程序状态寄存器|

其中，LR 保存调用或异常返回相关信息，PC 记录故障发生时的执行位置，xPSR 反映处理器当前的程序状态。

如果芯片启用了 FPU，并且浮点上下文需要保存，还可能形成扩展栈帧，额外保存浮点寄存器与 FPSCR 等内容。

在 RTOS 系统中，需要首先判断异常发生时使用的是 MSP 还是 PSP，否则可能读取到错误的栈帧。

如果在异常入栈或异常返回过程中再次发生错误，故障处理会进一步复杂化。例如，栈空间本身已经损坏，或者 FPU 懒加载状态保存失败，就可能出现以下错误：

- Stacking Error：异常入栈错误。
    
- Unstacking Error：异常出栈错误。
    

这类问题通常表明系统运行时的上下文环境已经严重受损。

在 RTOS 环境中，HardFault 还经常与以下问题有关：

- 任务栈溢出。
    
- 上下文切换异常。
    
- 临界区管理不当。
    
- 中断服务程序中误用 RTOS 接口。
    

### 2. NMI（不可屏蔽中断）

NMI（Non-maskable Interrupt），即不可屏蔽中断，是 Cortex-M 处理器的一种系统异常。

NMI 具有较高的异常优先级，不能通过普通的中断屏蔽机制关闭。其优先级仅低于 Reset。

### 3. MRS 与 MSR 指令

MRS（Move from Special register）和 MSR（Move to Special register）是 ARM 处理器用于访问特殊寄存器的指令。

- **MRS**：将特殊寄存器的值读取到通用寄存器中。
    
- **MSR**：将通用寄存器的值写入特殊寄存器中。
    

#### 3.1 典型应用

- 系统初始化：配置处理器相关控制寄存器。
    
- 异常处理：保存和恢复处理器上下文。
    
- 中断管理：设置中断屏蔽状态。
    
- 获取处理器状态：读取当前处理器状态和相关信息。
    

#### 3.2 注意事项

**1. 特权级别**

绝大多数系统寄存器都有特定的访问权限要求。

例如，在 ARMv8-A 架构中，操作 `SCTLR_EL1` 通常需要在 EL1 或更高权限级别下执行。在 EL0 用户模式下尝试访问受限的系统寄存器会触发异常。

**2. 指令屏障**

使用 MSR 修改影响处理器执行行为的系统寄存器后，通常需要根据寄存器的具体要求执行指令屏障。

- `ISB`（Instruction Synchronization Barrier）：指令同步屏障，清空流水线，确保后续指令按照新的处理器状态执行。
    
- `DSB`（Data Synchronization Barrier）：数据同步屏障，确保此前的数据访问及相关操作完成。
    

例如，修改 MMU 相关配置时，需要按照 ARM 架构规定的顺序执行必要的 DSB 和 ISB 指令。

**3. 寄存器宽度**

使用 MSR 写入时，如果系统寄存器的有效宽度小于通用寄存器宽度，高位的处理方式取决于具体寄存器定义。

使用 MRS 读取时，同样需要关注目标寄存器的有效位宽及高位处理规则。

**4. 立即数格式的限制**

对于部分 MSR 指令，立即数并不是任意数值，而是用于指定特定控制位的位掩码。

例如，`DAIFSet` 和 `DAIFClr` 使用立即数指定需要设置或清除的中断屏蔽位。

#### 3.3 使用注意事项

1. 确认当前处理器架构和执行权限。
    
2. 修改关键控制寄存器后，根据架构要求使用 DSB、ISB 等屏障指令。
    
3. 查阅具体处理器的技术参考手册（TRM），确认寄存器的位字段定义和访问限制。
    

### 4. FreeRTOS 任务调度与 PendSV

PendSV（Pended Service Call，可挂起的系统调用）是 Cortex-M 处理器提供的一种系统异常，FreeRTOS 通常使用 PendSV 完成任务上下文切换。

PendSV 的异常优先级通常配置为最低，以保证高优先级中断能够优先得到响应。

#### 4.1 PendSV 的触发方式

可以通过向 NVIC 的 PendSV 悬起寄存器写入 1，主动悬起 PendSV 异常。

当调度器决定需要切换任务时，例如 SysTick 触发调度或者任务主动调用 Yield 接口，通常不会立即完成任务切换，而是悬起 PendSV 异常。

当其他高优先级异常处理完成后，处理器执行 PendSV 异常处理程序，完成任务上下文切换。

这种机制可以将任务切换统一放在 PendSV 中处理，避免在多个中断服务程序中直接执行上下文切换。

#### 4.2 任务上下文切换 (Context Switch)

单核 MCU 的 CPU 在任意时刻只能执行一条指令。多个任务能够表现为同时运行，是因为处理器通过高频率的任务调度，在不同任务之间切换执行。

每次任务切换主要包含两个步骤：

1. **保存现场**：保存当前任务尚未执行完成的寄存器状态和堆栈指针。
    
2. **恢复现场**：恢复下一个任务之前保存的寄存器状态和堆栈指针。
    

在 Cortex-M 中，异常进入时硬件会自动保存以下 8 个寄存器：

基本栈帧：`R0～R3、R12、LR、PC、xPSR`

PendSV 处理程序还需要通过汇编代码手动保存另外 8 个寄存器：

`R4～R11`

因此，在不考虑 FPU 扩展上下文的情况下，一个任务的基本上下文包含：

[  
8+8=16\text{ 个寄存器}  
]

每个寄存器占用 4 字节，因此：

[  
16\times4=64\text{ Bytes}  
]

这 64 字节只是基本上下文所需的空间。实际任务栈还需要容纳函数调用、局部变量、中断嵌套及其他运行时数据，因此通常需要分配更多空间。

#### 4.3 vTaskDelay 的底层执行过程

当应用程序调用 `vTaskDelay(10)` 时，FreeRTOS 内部主要执行以下操作：

1. 当前任务从就绪链表中移除。
    
2. 当前任务进入延时阻塞状态，并加入相应的延时链表。
    
3. 调度器选择其他就绪任务运行。
    
4. 通过 PendSV 异常完成任务上下文切换。
    
5. SysTick 周期性产生系统节拍，中断处理程序更新系统时基。
    
6. 延时时间到达后，任务重新进入就绪状态，等待调度器执行。
    

其中，`vTaskDelay(10)` 中的 10 表示系统节拍数 Tick，实际延时时间由 FreeRTOS 的系统节拍频率 configTICK_RATE_HZ 与 Tick共同决定。

1. `configTICK_RATE_HZ = 1000`：一个 Tick 为 1ms。
    
2. `configTICK_RATE_HZ = 100`：一个 Tick 为 10ms。
    
	1. `configTICK_RATE_HZ = 100` 时，`vTaskDelay(10)` 对应 100ms 的延时请求。
    

### 5. ARM Cortex-M 寄存器组

Cortex-M 处理器包含 R0～R15 共 16 个通用寄存器，每个寄存器宽度为 32 位。

其中：

- R0～R12：13 个通用寄存器。
    
- R13：栈指针（SP）。
    
- R14：链接寄存器（LR）。
    
- R15：程序计数器（PC）。
    

按照寄存器编号，还可以将其分为：

- **低寄存器**：R0～R7。
    
- **高寄存器**：R8～R12。
    

低寄存器可以被大多数 Thumb 指令访问。高寄存器的访问受到部分 16 位 Thumb 指令编码的限制，32 位 Thumb-2 指令具有更完整的寄存器访问能力。

通用寄存器在复位后的初始值通常不确定。程序需要根据实际用途对相关寄存器进行初始化。

#### 5.1 R13：SP 栈指针

SP（Stack Pointer）用于指向当前使用的栈空间，负责管理函数调用、局部变量以及程序运行过程中的临时数据。

Cortex-M 处理器提供两个栈指针：

- **MSP（Main Stack Pointer，主堆栈指针）**：主要用于操作系统内核和异常处理。
    
- **PSP（Process Stack Pointer，进程堆栈指针）**：通常用于运行 RTOS 的应用任务。
    

MSP 和 PSP 是两个独立的栈指针寄存器，同一时刻处理器根据当前运行模式和 CONTROL 寄存器的配置选择其中一个作为当前 SP。

复位后，处理器默认使用 MSP。

在 Cortex-M 中：

- Handler 模式始终使用 MSP。
    
- Thread 模式可以使用 MSP 或 PSP。
    
- RTOS 通常使用 PSP 运行任务，使用 MSP 处理异常。
    

异常发生时，处理器首先根据异常发生前的运行模式和栈指针选择规则，确定异常栈帧的保存位置。

如果异常发生前处于使用 PSP 的 Thread 模式，硬件会将异常栈帧保存到 PSP，然后切换到 Handler 模式，并使用 MSP 执行异常处理程序。

Handler 模式始终使用 MSP。

##### 5.1.1 PSP 的配置

可以使用 MSR 指令设置 PSP：

```
MSR     PSP, R0      ; 将 R0 的值写入 PSP
```

如果需要在异常返回后让处理器使用 PSP，还需要设置异常返回值 LR 的相应位。

```
ORR     LR, LR, #0x04    ; 将 LR 的 bit[2] 置 1
```

当异常返回使用相应的 EXC_RETURN 编码时，bit[2] 为 1 表示返回 Thread 模式后使用 PSP。

EXC_RETURN 的 bit[2] 用于选择异常返回后使用的栈指针：

- bit[2] = 0：返回 Thread 模式后使用 MSP。
- bit[2] = 1：返回 Thread 模式后使用 PSP。


##### 5.1.2 为什么需要两个堆栈指针

如果任务和中断共用一个堆栈，一旦任务发生栈溢出，就可能覆盖中断处理程序或内核使用的栈空间，导致系统异常甚至无法正常恢复。

双堆栈机制可以将任务运行时使用的栈与异常处理使用的栈分开管理，降低任务栈溢出对内核运行环境的影响。

#### 5.2 R14：LR 链接寄存器

LR（Link Register）是链接寄存器，用于保存函数调用或异常处理过程中的返回地址。

它的主要作用是记录程序的返回位置，使处理器能够在函数执行结束或异常处理完成后，继续执行原来的程序。

##### 5.2.1 保存函数返回地址

执行子程序调用指令 `BL` 时，处理器会自动将返回地址保存到 LR 中。

例如：

```
main:
    ...
    BL  subroutine      ; 调用子程序
    MOV R0, #5          ; 子程序返回后继续执行
    ...

subroutine:
    ...                ; 子程序代码
    BX  LR             ; 返回调用位置
```

在这个过程中，LR 保存子程序执行完成后需要返回的位置。

`BX LR` 将 LR 中保存的地址加载到 PC，子程序执行完成后，可以通过 BX LR 返回调用位置。

由于 Cortex-M 使用 Thumb 指令集，LR 中保存的返回地址还包含相应的 Thumb 状态标志。


##### 5.2.2 异常处理时的状态保存

当处理器发生异常时，会自动生成异常返回信息，并将相应的异常返回编码保存到 LR 中。

在 Cortex-M 中，这个特殊的返回值称为 EXC_RETURN。

异常处理程序执行完成后，可以通过异常返回机制恢复此前被中断的程序上下文。

在 Cortex-M 异常处理过程中，LR 可以保存 EXC_RETURN 编码。

##### 5.2.3 作为临时寄存器使用

在函数内部，如果返回地址已经被安全地保存到栈中，LR 也可以作为临时寄存器使用。

例如：

```
PUSH    {LR}       ; 保存返回地址
...
POP     {PC}       ; 恢复返回地址并返回
```

需要注意，LR 并不是普通的永久存储寄存器。如果函数内部还需要执行其他函数调用，就必须妥善保存原来的返回地址，避免被新的函数调用覆盖。

##### 5.2.4 不同 ARM 架构中的 LR

在传统 ARM A/R 架构中，处理器具有多个工作模式，不同异常模式可以拥有独立的Banked（银行化）寄存器。

例如：

- 用户模式和系统模式共用 LR。
    
- SVC 模式具有独立的 LR_svc。
    
- Abort 模式具有独立的 LR_abt。
    
- Undefined 模式具有独立的 LR_und。
    
- IRQ 模式具有独立的 LR_irq。
    
- FIQ 模式具有独立的 LR_fiq。
    

Banked ：同一个寄存器编号在物理上具有多个独立的寄存器副本，但在逻辑上使用相同的寄存器名称。处理器根据当前运行模式，自动选择对应的寄存器副本。

Banked 寄存器机制可以使不同异常模式拥有独立的寄存器现场，减少异常处理过程中保存和恢复寄存器的操作。

Cortex-M 不采用传统 ARM A/R 架构的异常模式和银行化寄存器机制，而是通过 MSP、PSP、异常自动入栈和 EXC_RETURN 完成相应的上下文管理。


#### 5.3 R15：PC 程序计数器

PC（Program Counter）是程序计数器，用于控制处理器的指令执行位置。

处理器执行指令时，主要经历以下三个阶段：

1. **取指**：从存储器中读取指令。
    
2. **译码**：识别指令类型和操作数。
    
3. **执行**：执行指令并将结果写回寄存器。
    

由于处理器采用流水线结构，读取 PC 时得到的值可能与当前正在执行的指令地址存在偏移。

传统 ARM 处理器在 ARM 状态下读取 PC 时，通常会得到当前指令地址加 8 的值。

Cortex-M 只支持 Thumb 指令集，不支持 ARM 状态。对于 Cortex-M3，读取 PC 时通常返回当前指令地址加 4 的值。

例如：

```
0x1000:    MOV R0, PC
```

执行这条指令时：

```
R0 = 0x1004
```

PC 不仅用于指示指令执行位置，还可以通过修改 PC 的值改变程序执行流程。

如果向 PC 写入新的地址，就会引起程序分支，但不会自动更新 LR。

通过 BX、BLX 等分支指令进行间接跳转时，目标地址最低位用于表示指令集状态。Cortex-M 只支持 Thumb 指令集，指令地址至少需要满足半字对齐要求。

### 6. Cortex-M 特殊功能寄存器

除了 R0～R15 通用寄存器，Cortex-M 还提供一组特殊功能寄存器，用于管理处理器状态、中断屏蔽和运行模式。

主要包括：

- 程序状态寄存器组（PSRs / xPSR）。
    
- 中断屏蔽寄存器组（PRIMASK、FAULTMASK、BASEPRI）。
    
- 控制寄存器（CONTROL）。
    

这些寄存器需要通过专用的 MRS 和 MSR 指令访问。

基本格式如下：

```
MRS <gp_reg>, <special_reg>    ; 读取特殊寄存器到通用寄存器
MSR <special_reg>, <gp_reg>    ; 将通用寄存器的值写入特殊寄存器
```

#### 6.1 程序状态寄存器 PSRs / xPSR

程序状态寄存器用于记录处理器当前的程序状态。

Cortex-M 的程序状态寄存器由以下三个子状态寄存器组成：

- **APSR（Application Program Status Register）**：应用程序状态寄存器，保存算术运算产生的条件标志位。
    
- **IPSR（Interrupt Program Status Register）**：中断程序状态寄存器，保存当前异常编号。
    
- **EPSR（Execution Program Status Register）**：执行状态寄存器，保存与指令执行状态相关的信息。
    

三个子状态寄存器组合后称为 xPSR。

通过 MRS 指令，可以分别读取 APSR、IPSR、EPSR，也可以通过 xPSR 一次性读取组合后的状态信息。

需要注意，APSR、IPSR、EPSR 和 xPSR 的写入权限及支持的访问形式并不相同，具体以 Cortex-M 架构手册为准。

#### 6.2 中断屏蔽寄存器

Cortex-M 提供 PRIMASK、FAULTMASK 和 BASEPRI 等寄存器，用于控制异常的响应和屏蔽。

##### 6.2.1 PRIMASK

PRIMASK 是一个只有 1 位有效位的寄存器，用于屏蔽所有可配置优先级的异常。

- PRIMASK = 0：不通过 PRIMASK 屏蔽异常。
    
- PRIMASK = 1：关闭所有可屏蔽异常，只允许 NMI 和 HardFault 响应。
    

设置 PRIMASK 后，NMI 和 HardFault 仍然可以响应。

PRIMASK 复位后的默认值为 0。

##### 6.2.2 FAULTMASK

FAULTMASK 是一个只有 1 位有效位的寄存器，用于屏蔽除 NMI 以外的异常。

- FAULTMASK = 0：不通过 FAULTMASK 屏蔽异常。
    
- FAULTMASK = 1：除 NMI 外，其他异常均被屏蔽。
    

FAULTMASK 复位后的默认值为 0。

##### 6.2.3 BASEPRI

BASEPRI 用于设置中断优先级屏蔽阈值。

当 BASEPRI 被设置为某个非零值时，所有优先级数值大于或等于该阈值的异常都会被屏蔽。

需要注意：

- 优先级数值越小，实际优先级越高。
    
- 优先级数值越大，实际优先级越低。
    
- BASEPRI = 0 时，不通过 BASEPRI 屏蔽任何异常。
    

BASEPRI 的有效位宽取决于处理器实现的优先级位数。

以上中断屏蔽寄存器需要通过 MRS 和 MSR 指令访问，相关操作需要满足处理器的特权级要求。

#### 6.3 控制寄存器 CONTROL

CONTROL 寄存器主要用于控制 Thread 模式下的特权级别和栈指针选择。

其中：

- CONTROL[0]：控制 Thread 模式的特权级别。
    
- CONTROL[1]：选择 Thread 模式使用的栈指针。
    

##### 6.3.1 CONTROL[0]：特权级别控制

- 0：Thread 模式运行在特权级。
    
- 1：Thread 模式运行在非特权级。
    

Handler 模式始终运行在特权级。

##### 6.3.2 CONTROL[1]：栈指针选择

- 0：Thread 模式使用 MSP。
    
- 1：Thread 模式使用 PSP。
    

Handler 模式始终使用 MSP，不受 CONTROL[1] 的影响。

因此，CONTROL 寄存器主要用于配置 Thread 模式的运行权限和栈指针选择。

在 RTOS 中，通常通过 CONTROL 配置任务运行时的栈指针，使任务使用 PSP，而异常处理使用 MSP。
